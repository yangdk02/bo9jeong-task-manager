# 보구정 과업 관리 도구 인수인계

최종 갱신: 2026-10-27

## 1. 제품 상태

`보구정 과업 관리 도구` MVP는 로컬 실행과 Vercel 검증 배포가 가능한 상태입니다.

- 운영 URL: https://bo9jeong-task-manager.vercel.app
- 프론트엔드·서버: Next.js 16 App Router, React 19, TypeScript
- 로컬 저장: CSV 11개와 로컬 파일
- 배포 저장: Supabase Postgres 11개 테이블과 비공개 Storage
- 결과 보고서: PptxGenJS로 요청 시 생성하는 편집 가능한 PPTX
- 로그인·권한: 구현하지 않음. 랜딩의 담당자 선택은 조회 관점 선택 기능임

## 2. 업무 구조

```text
프로젝트 → 과업 → 작업 → 작업 파일
    │        │       └ 작업 담당자
    │        ├ 과업 담당자
    │        └ 플레이스 월별 방문자 수
    ├ 프로젝트 담당자
    └ 자료 DB

작업·자료 → 댓글·활동 기록
```

- 프로젝트는 업체, 계약 기간과 과업 묶음입니다.
- 과업은 계약한 업무 항목이며 표준 목록에서 선택하고, 목록에 없을 때만 `기타`로 직접 입력합니다.
- 작업은 실무자가 등록하는 최소 실행 단위입니다.
- 상태가 `completed`인 작업 1행을 실적 1건으로 계산하며 첨부 파일 수는 실적 수에 영향을 주지 않습니다.
- 프로젝트·과업·작업에는 여러 담당자를 연결할 수 있습니다.
- 담당자 부서는 `people.department`에 직접 저장합니다.

## 3. 구현 화면

1. 랜딩
   - 담당자 이름 자동완성 검색
   - 신규 담당자와 부서 추가
   - `BO9JEONG WORKSPACE` 표기
2. 대시보드
   - 선택 월의 전체·완료·남은 과업과 과업 기준 진행률
   - 프로젝트별 진행률, 최근 작업 5건
3. 프로젝트
   - 목록, 검색, 상태·계약 만료 분류
   - 생성·수정·삭제
   - 표준 과업 체크리스트, 목표 수량·단위, 복수 담당자
4. 프로젝트·과업 상세
   - 조회 월 이동
   - 부서별·담당자별 필터
   - 목표, 완료, 잔여, 초과 수행 표시
5. 작업
   - 생성·수정·삭제
   - 날짜, 제목, URL, 메모, 상태, 복수 담당자
   - 여러 증빙 파일, 교체, 개별 삭제, Ctrl+V 붙여넣기
   - 첨부 파일을 자료 DB에도 복사 등록
   - 댓글과 자동 활동 기록
6. 자료 검색
   - 프로젝트, 자료명, 유형, 담당자, 부서 검색
   - 생성·수정·삭제, 파일 교체, 댓글·활동
7. 결과 보고서
   - 프로젝트와 시작 월·종료 월 선택
   - 실시간 페이지 미리보기
   - 편집 가능한 PPTX 다운로드
8. 자료 백업 및 복구
   - CSV 11개와 등록 파일을 ZIP으로 다운로드
   - 구조·ENUM·FK·중복 연결 검사 후 ZIP 복구
9. 이용 가이드

## 4. 집계 규칙

- 월간 반복 과업은 모든 조회 월에 표시합니다.
- 일회성 과업은 `created_at`이 속한 월에만 표시하며 다음 달로 이월하지 않습니다.
- 월별 실적은 작업일이 조회 월에 속하고 상태가 `completed`인 작업만 계산합니다.
- 과업 수량 진행률은 `완료 작업 수 / target_count`입니다.
- 초과 수행은 완료 작업 수가 목표보다 많을 때 별도로 표시합니다.
- 대시보드 완료 과업은 조회 월의 완료 작업 수가 목표 이상인 과업입니다.
- 대시보드 진행률은 `완료 과업 수 / 조회 월 전체 과업 수`입니다.

## 5. 네이버 플레이스 방문자 수

- 과업명이 정확히 `플레이스 관리 (월 통계 캡처)`일 때만 작업 등록·수정에서 방문자 수를 입력합니다.
- `place_monthly_metrics`는 과업·연월별 한 행만 저장합니다.
- 행 없음은 `미입력`, 저장된 0은 실제 수치 0, 전월 행 없음은 `전월 자료 없음`입니다.
- 전월이 0이고 조회 월이 양수이면 증감률을 `신규`로 표시합니다.
- 네이버에서 자동 수집하지 않습니다.
- 보고서에는 대표 캡처와 전월·조회 월 비교표를 같은 페이지에 배치합니다.

## 6. 보고서 규칙

- UI에서는 날짜가 아니라 시작 월·종료 월을 선택합니다.
- 내부 보고 기간은 시작 월 1일부터 종료 월 말일까지로 변환합니다.
- 월간 반복 과업은 선택 범위에 포함합니다.
- 일회성 과업은 생성 월이 선택 범위에 들어갈 때만 포함합니다.
- 선택 기간에 완료된 작업만 실적과 증빙으로 포함합니다.
- 보고서 표지, 미리보기, PPTX가 동일한 과업·작업 필터를 사용합니다.
- 페이지 수는 과업과 실적 수에 따라 자동 결정합니다.
- 보고서는 영구 테이블에 저장하지 않습니다.

## 7. 파일과 삭제

- 한 번의 작업·자료 저장 요청에 첨부하는 파일 합계는 4MB 이하입니다.
- 이미지, PDF, 일반 문서, 디자인 원본과 ZIP을 허용합니다.
- 동영상은 허용하지 않습니다.
- 로컬 파일 경로는 `storage/...` 논리 형식을 사용하고, Supabase Storage 내부 키는 영문 안전 경로를 사용합니다.
- 작업 삭제 시 작업 행, 담당자 연결, 작업 파일 메타데이터, 댓글과 실제 파일을 함께 삭제합니다.
- 자료 삭제 시 자료 행, 댓글과 실제 파일을 함께 삭제합니다.
- 삭제 직전 자동 백업과 휴지통은 없습니다. 필요한 경우 먼저 수동 ZIP 백업을 내려받습니다.

## 8. 저장소 구성

| 경로 | 용도 |
|---|---|
| `src/app` | 화면과 Route Handler |
| `src/components` | 클라이언트 UI 컴포넌트 |
| `src/lib/domain` | 스키마, 과업 기간, 플레이스 계산 규칙 |
| `src/lib/server` | 저장소, 업무 조회·변경, 백업, PPTX 생성 |
| `data/templates` | 빈 CSV 헤더 11개 |
| `data/seed` | 샘플 CSV 11개 |
| `data/seed-files` | 배포 샘플 파일과 논리 경로 매핑 |
| `data/local` | 로컬 실행 데이터, Git 제외 |
| `storage` | 로컬 등록 파일, Git 제외 |
| `supabase/schema.sql` | 배포 DB·Storage 스키마 |
| `scripts` | 로컬 초기화와 Supabase 설정 |

## 10. 검증과 실행

```powershell
npm install
npm run dev
npm test
npm run lint
npm run typecheck
npm run build
```

- 로컬 데이터가 없으면 템플릿 또는 seed에서 안전하게 시작해야 합니다.
- CSV가 비어 있어도 빈 상태 화면이 표시되어야 합니다.
- ENUM, FK, 중복 담당자 연결과 플레이스 과업 연결은 저장 전에 검증합니다.
- 파일 저장 실패 시 메타데이터만 남기지 않습니다.
- Vercel Hobby는 시연·검증용입니다. 실제 운영 전 플랜 적합성을 다시 검토합니다.
